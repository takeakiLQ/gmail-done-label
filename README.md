# Gmail ワンクリック処理済 — v1.1.0

Manifest V3のChrome拡張です。Gmailの上部へ **✉️要返信 ▾** と **✅処理済 ▾** を追加します。開いているスレッド／一覧で選択したメールに、次の操作を行います。

| 操作 | 結果 |
| --- | --- |
| ✉️要返信 | 要返信を付け、処理済を外す |
| ✅処理済 | 処理済を付け、要返信を外す |
| 要返信の▾ → このラベルを外す | 要返信だけを外す |
| 処理済の▾ → このラベルを外す | 処理済だけを外す |

取消は現在の対象からそのラベルを外す操作です。以前の操作履歴に戻す機能ではありません。取消で反対側のラベルを付けることもありません。複数選択では選択した全対象に同じ操作を行います。既読・未読、スヌーズ、ほかのラベルは変更しません。

OAuth・Google Cloud・APIキー・サーバーは不要です。Gmail標準のラベルメニューを操作します。コードのビルドも不要です。v1.0.8の既存動作は利用者から改善確認を受けました。v1.1.0の新しい状態切替と取消メニューの実機確認はまだです。

## 最初に行うこと（Gmailアカウントごとに1回）

Gmailの「設定」→「すべての設定を表示」→「ラベル」→「新しいラベルを作成」で、次の2つを作成してください。既にあるラベルは作成不要です。文字列をコピーし、余分な空白を入れず、階層ラベルにしないでください。

- `✅処理済`
- `✉️要返信`

同じGmailアカウントのラベルは別PCにも反映されます。別アカウントではそれぞれ作成してください。拡張へのメールアドレスやアカウントID設定は不要です。

## インストール・既存版の更新

1. `gmail-done-label-v1.1.0.zip` を展開します。
2. 新規導入なら、展開先を削除・移動しない固定フォルダーに置きます。
3. Chromeで `chrome://extensions` を開き、デベロッパーモードをオンにします。
4. 「パッケージ化されていない拡張機能を読み込む」で、manifest.jsonが直接入っているフォルダーを選びます。ソースZIPから入れる場合は `extension` フォルダーを選びます。
5. **既存版の更新は、前回読み込んだフォルダーへ新しい中身を上書き**し、拡張の再読み込みを押します。二重インストールしないでください。
6. Gmailも再読み込みし、拡張のバージョン1.1.0と2つのボタンを確認します。

プロファイルごと・PCごとに導入が必要です。ZIP方式には自動更新やChrome同期による自動導入はありません。社内ポリシーでデベロッパーモードが禁止されている場合は管理者の許可が必要です。

## 使い方と切替の流れ

返信を後で行うメールを開くか、一覧のチェックボックスで選び、「✉️要返信」を押します。返信や必要な仕事が終わったら「✅処理済」を押します。ラベルを外すだけなら、そのボタン横の「▾」から「このラベルを外す」を選びます。取消メニューはEscapeやメニュー外のクリックでも閉じられます。

状態切替は、反対側のラベルを外してから選んだラベルを付けます。Gmailのメニューを2回開く場合があります。最初の変更前に、必要な両ラベルの存在を確認します。2段階の切替はサーバー上での一括更新ではありません。途中で中断した場合は前のラベルだけが外れた状態になり得るため、「途中で止まりました」と通知します。対象を確認して再度目的の状態ボタンを押してください。各書込み前に対象変更を確認し、別メールに切り替わった場合は中止します。

操作中はボタンを無効にします。他のメールへ移動したり標準ラベルメニューを操作したりせず、完了通知を待ってください。完了通知はGmail UIへの操作実行を示し、Gmail APIでサーバー保存を照合するものではありません。Gmail自身のエラー表示と保存後のラベルを確認してください。

会話表示や検索結果の一括選択への適用範囲はGmail標準のラベル操作に従います。閲覧ペインでは一覧の選択対象が優先です。後から届いた新着メールを自動で処理済にすることはありません。添付の印刷・転送などの実作業は利用者が行います。

## 配布・更新

### A. すぐ使えるZIP配布

配布用ZIPを社内共有フォルダー等へ置き、上記の手順で各PCへ読み込みます。受け取った人がソースを確認できる構成です。社内への実際の送付はこの成果物には含みません。

更新時は新ZIPを展開し、既存のインストール先のファイルを置き換え、`chrome://extensions` で当該拡張の「再読み込み」を押し、Gmailタブも再読み込みします。`manifest.json` のversionを上げ、配布先全PCで更新してください。フォルダーを変える場合は古い拡張を削除してから新しいものを読み込み、二重インストールを避けます。

### B. Chrome ウェブストア配布（継続運用向け）

1. 配布用ZIPを使い、Chrome Web Storeの開発者登録・ダッシュボードから新規アイテムとしてアップロードします。登録時の費用や公開条件は公式画面で確認してください。
2. 説明文、アイコン、**実際のGmailで撮影した**スクリーンショット、サポート連絡先、プライバシー情報を登録します。`PRIVACY.md` を公開する際には運営者と連絡先を記載し、公開URLを用意します。
3. 公開範囲を目的に合わせて設定します。限定公開（unlisted）は検索には出ませんが、URLを知っている人のアクセスを制限する仕組みではありません。組織内に制限する場合はWorkspace／ストアの組織向け公開設定と管理者の設定を確認します。
4. 審査・公開後、ストアURLを各PCへ配布します。ストア配布では通常の更新配信を利用できます。
5. 更新はversionを上げたZIPを同じアイテムへアップロードし、必要な審査・公開を行います。

この成果物はストアへの登録・審査・公開を済ませたものではありません。通常のWindows／macOSで、ローカルCRXファイルを配るだけで通常インストールできるとは想定していません。

### C. 管理対象の社内PC

ストアに組織向け公開した拡張を、Chrome管理コンソールやグループポリシーで許可／自動インストールする運用が可能です。管理者は発行された拡張IDを使用します。ストア外の自社ホスティングは別途署名鍵、更新マニフェスト、HTTPS配信、企業管理ポリシー等が必要で、OSや管理方法による制約があります。小規模利用はA、管理対象端末への継続配布はB＋管理ポリシーが扱いやすい構成です。

## 必要権限と安全性

| 項目 | 内容 |
| --- | --- |
| 対象サイト | `https://mail.google.com/mail/*` のトップフレームだけ |
| API permissions | `permissions` は宣言していません |
| ホストアクセス | `content_scripts.matches` でGmail画面にスクリプトを読み込みます。Gmailのサイトデータを読み取り・変更する権限表示が発生し得ます |
| OAuth・API | 使用しません。認証トークン・APIキー・Client IDは不要です |
| 通信 | 拡張自身から外部サーバーへの通信はありません。操作の反映はGmail自身の通信です |
| 保存 | 本文・添付・メールアドレス・操作履歴・認証情報は収集・保存・送信しません。ブラウザーstorageも使用しません |
| 実行コード | 同梱のJS／CSSのみ。外部ライブラリ、リモートコード、解析サービスはありません |

技術的にはGmailに挿入されるスクリプトは表示DOMにアクセスできます。この実装はツールバー・ラベル名・チェック状態・対象のDOM要素とページURLだけを操作中のメモリーで扱い、本文・件名・送信者の内容を読み取って記録しません。アカウント番号を含み得るURLもログ出力しません。パスワードやCookieの読み取り処理はありません。配布元を確認し、ソースも確認してから利用してください。

ラベルの追加・取り消しを行います。送信・メール削除・アーカイブ・移動は実装していません。Gmailの標準チェック状態を操作し、対象ラベルがチェック済みであることと他のラベルの状態が変わっていないことを確認してから「適用」します。ページ移動や選択変更を検出した場合は適用を中止します。成功後はGmail標準ラベルボタンにフォーカスを戻し、閉じたか確認しながら段階的にマウス操作を送ります。閉じない場合はEscapeを試します。中止時は未適用のチェック変更を破棄するためEscapeを先に使います。即時反映UIではチェック変更が既に保存されるため、メニューを閉じても取り消しにはなりません。残った場合はGmail標準の「ラベルを付ける」ボタンを押して閉じてください。

## 対応範囲・制約

- PC版Gmailの日本語・英語表示を対象とします。モバイル、埋め込みフレーム、メール作成画面、他言語は対象外です。
- Gmail UIは公開された安定APIではありません。Google側のDOM・文言変更やA/Bテストで修正が必要になる可能性があります。
- ラベルは事前に作成します。名前に余分な空白がある場合、階層ラベルの場合などは認識しません。
- 操作中は他のラベルメニューやメール選択を操作しないでください。拡張は操作開始前に開いているメニューやダイアログを検出すると中止します。
- **新機能のログイン済みGmailでの実機試験は未実施です。** 同梱のオフライン模擬画面試験で主要動作を確認しています。社内展開前に次の受入確認を行ってください。

### 実機の受入確認

1. テストメールを開き、1クリックで「✅処理済」が付くか確認します。
2. もう1回押してもラベルが外れないことを確認します。
3. 一覧で2件以上選び、選んだメールだけに付くことを確認します。
4. 既存の他ラベルが残り、一部だけ処理済だった選択にも追加できることを確認します。
5. Gmailを再読み込みして保存結果を確認します。
6. 同じアカウントを別PCで開き、ラベルが反映されることを確認します。
7. 別アカウントでも、そのアカウントに両ラベルを作成した後に使用できることを確認します。
8. 要返信→処理済→要返信の各切替で、反対側のラベルが外れることを確認します。
9. 各取消メニューで対象ラベルだけが外れ、反対側・他ラベル・既読状態が変わらないことを確認します。
10. 再読み込み直後の初回と、次のメールでもメニューが閉じることを確認します。

## トラブル時

| 症状 | 確認・対処 |
| --- | --- |
| ボタンが出ない | 拡張が有効か確認しGmailを再読み込み。メールを開くか一覧で選択。Gmailが日本語／英語か、サイトアクセスや企業ポリシーで止まっていないか確認 |
| ラベル作成の案内が出る | 同じGmailアカウントに、完全一致の `✅処理済` と `✉️要返信` を作成。余分な空白や階層を確認 |
| メニューを特定できない | メニューを閉じて再読み込み。Gmail UI変更の可能性があるため、標準のラベル操作を使用 |
| 操作後ラベルが見えない | Gmailの接続エラーを確認し、再読み込みして確認。適用操作の通知はサーバー保存の保証ではありません |
| 操作中に対象が変わった | 残ったメニューをEscで閉じ、対象を選び直す |
| ボタンが重複する | 旧版や別フォルダーからの二重インストールを削除 |

## 将来「⏳保留」「👤相手待ち」を追加する

`extension/config.js` のactionsに項目を追加します。例えば配列を次のようにします。

```js
actions: Object.freeze([
  Object.freeze({ id: "reply", label: "✉️要返信", undo: true, clears: ["✅処理済"] }),
  Object.freeze({ id: "done", label: "✅処理済", undo: true, clears: ["✉️要返信"] }),
  Object.freeze({ id: "pending", label: "⏳保留" }),
  Object.freeze({ id: "waiting", label: "👤相手待ち" })
])
```

各アカウントにも同名ラベルを作成してから、拡張とGmailを再読み込みしてください。`clears` に指定したラベルは付与前に外します。指定しなければ独立して追加されます。`undo: true` でそのラベルだけを外す取消メニューが付きます。配布時は同じconfig.jsを全PCへ配布します。

API方式に変更する場合は別実装が必要です。この版にはOAuth設定項目やAPIへのフォールバックはありません。将来APIを採用する際は、OAuthクライアントと拡張IDの対応、同意画面、使用スコープ、組織内／個人の認証運用を改めて設計してください。

## ソースと検証

```
gmail-done-label/
  extension/
    manifest.json     Manifest V3・対象サイトの宣言
    config.js         追加するラベルとボタンの定義
    content.js        Gmail UI検出・操作・ガード
    content.css       ボタン・通知のスタイル
    icons/            ローカルアイコン
  tests/
    fixture.html      ログイン不要の模擬画面（実際のGmailではない）
    run.cjs           オフラインUI契約試験
  build.ps1          配布・ソースZIPの作成
  package.json       試験だけの依存関係と実行コマンド
  README.md
  PRIVACY.md
  TEST-REPORT.md
  LICENSE
```

Node.jsを用意し、ソースのルートフォルダーで `npm install`、`npm test` の順に実行します（依存関係の取得にネット接続が必要です）。Playwrightが既に使える環境では `node tests/run.cjs` でも試験できます。既定はWindowsの通常インストール先のChromeです。別の環境では `CHROME_PATH` にChrome／Chromiumの実行ファイルを指定します。Playwrightは試験だけの依存関係で、拡張の利用には不要です。

PowerShellで `./build.ps1` を実行すると、親フォルダーへ配布用ZIPとソースZIP、SHA-256一覧を作成します。利用者側でこの作業は不要です。
